# V2 移动目标 · 现场投屏

V1 保留固定目标。V2 由 PLC 在夹紧与张开坐标之间往返移动目标，夹爪沿用现场设置的定位速度。目标每到端点抽取下一程时长，默认范围为 2.3–5.2 秒。每程使用三次缓动曲线 `3t² − 2t³`，端点慢、中段快。暂停时锁定目标，夹爪停稳后沿用原程序的窗口判分。解锁后目标从锁定位置向原方向继续，重新缓动起步。

使用排行榜版本时，显示协议升级为 3，寄存器总数仍为 26。请参照[排行榜实机接入](Leaderboard.md#接入真实比赛)。下文寄存器表描述原 V2 协议。

## 1. 在电脑预演

在仓库的 `display` 目录运行 `npm ci` 和 `npm run demo`，打开 http://127.0.0.1:3000。默认预演固定目标。用 `npm run demo -- --moving` 预演移动目标。回放自动演示暂停、停稳和显示成绩；实机中由实体暂停按钮触发这些动作。Windows 显示分辨率选 **2560 × 1440**，把浏览器放到电视上，点“全屏”。页面按 16:9 居中缩放。网页按 PLC 实际模式显示「固定目标」或「移动目标」。

## 2. 更新 TIA Portal 工程

1. 导入 `plc/v20/FB_FunFairTarget.scl` 和本版本的 `plc/v20/FunFairDisplay.scl`，生成目标 FB、显示 FB 和显示 DB。新版 DB 的 `Registers` 范围为 `[0..25]`。创建一个非保持实例调用目标 FB。
2. 每次 OB1 扫描按 **目标 FB → 现有游戏 FB → 显示 FB → MB_SERVER** 的顺序调用。目标 FB 需要同一首扫位、实体暂停 DI，张开/夹紧设定，以及游戏实例 DB 的 `State`（此处读取上一扫描状态）。
3. 把原来固定的游戏目标设定接到目标 FB 的 `FixedTarget_um`。把目标 FB 的 `HighDifficulty` 接到 BOOL 变量或选择开关。FALSE 选固定目标，TRUE 选移动目标。游戏 FB 和显示 FB 的 `TargetPosition_um` 都接到目标 FB 实例的 `Target_um`。显示 FB 的 `ActiveMode` 接目标 FB 实例的同名输出。
4. `MB_HOLD_REG` 保持连接完整数组 `"DB_FunFairDisplay".Registers`，使用 ANY 指针的项目将长度更新为 **WORD 26**。编译硬件和软件后下载。在线确认签名、协议版本分别是 `4646` 和 `0002`（十六进制）。

| 零基偏移 | V2 变化 |
|---|---|
| 0–23 | 延续 [V1 布局](Display-V1.md#寄存器布局)，偏移 1 的协议版本变为 2 |
| 24 | PLC 当前模式，1 固定、2 移动 |
| 25 | 保留字，PLC 写 0 |

网页服务绑定到电脑本机，通过 Modbus TCP 读取显示区。顶部标签取自偏移 24。暂停锁住或正在判分时修改 HighDifficulty，PLC 在恢复往复后应用新模式。

## 3. 现场联调

1. 在电脑的 `display` 目录设置 `$env:PLC_HOST = "192.168.0.150"` 并执行 `npm start`。确认页眉显示 PLC 在线。
2. 在 V1 核对原来的目标、位置及偏差。夹爪往复时将 HighDifficulty 设为 TRUE，确认目标往返、端点减速，夹爪速度仍为原设置。
3. 指针进入窗口时，窗口边框和目标带变绿，页面显示“现在暂停”。按实体按钮后确认目标冻结，待停稳再核对 `Success`。再解锁确认两者继续移动。
4. 连续试打几轮。若电视显示落后于实物，以电视游戏模式及实拍对比确认现场延迟。页面刷新和电视显示会带来延迟，停稳后的最终结果以 PLC 数据为准。

页面采用雄克官网蓝 `#009EE0` 与白色为主色，轨道和指针使用高对比色便于远观。[雄克中国官网](https://schunk.com/cn/zh)


## 4. 调整刷新与检查模式回读

电脑端默认每次读取完成后等待 20 ms。可在启动前设置 `$env:PLC_POLL_MS = "20"`，例如按现场通信负载调整到 30 或 50。每次只发一个读取请求，实际采样间隔还包括 PLC 响应和处理时间。若缩短轮询后位置仍分段更新，在 TIA Trace 查看游戏块的 ActualPosition_um，以确认夹爪周期反馈的更新节奏。

如果顶部标签与预期不同，先看 HighDifficulty 和目标 FB 的 ActiveMode，再核对显示 FB 的同名引脚与 Registers[24]。恢复往复时，ActiveMode 应跟随 HighDifficulty 变为 1 或 2。
