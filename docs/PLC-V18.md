# FunFair：TIA Portal V18 第一版程序

目标：CPU 1211C DC/DC/DC；SCHUNK EGU 60-PN-M-B（1491558），用户报告固件 V5.3，手册核对版本为 V5.3.1。补丁版本、CPU 订货号/固件尚未读取。

已交付 `plc/FB_FunFair_StopGame.scl`：可导入的 SCL 外部源文件草稿。没有 TIA 编译器或现场设备，**尚未在 V18 编译、未通过 PLCSIM/实机验证，不是可直接下载运行的成品工程**。该 FB 是游戏控制层；设备初始化、故障确认、PN 数据有效性和硬件安全功能由工程的驱动层提供。

## v0.2：已确认的新玩法

进入已完成初始化、运行许可满足的游戏模式后自动往复。同一个瞬时按钮每次完整“按下→松开”算一次点击，在松开时切换：运动中点击停止并判分，结果状态点击开始下一回合。

- `ButtonReleased=TRUE` 表示松开，FALSE 表示按下，由现场接线或输入归一化实现。
- `ReleaseEdgeDetector : R_TRIG` 检测过滤后松开信号的上升沿；`PressEdgeDetector` 也用 R_TRIG 检测按下，配对后才生成一次点击。
- 按住不切换；初始松开不会触发停止；上电按钮按住时等待稳定松开再自动开始，首次松开不算点击。
- 默认按下滤波 20 ms、松开滤波 5 ms；均为待现场验证的参数。
- 停止/判分期间的点击忽略，不排队。按下若发生在停止期间、松开发生在结果阶段，也不恢复；必须在结果阶段完成新的完整点击。
- 每回合进入结果后保持停止与成绩，下一次点击清成绩并恢复。恢复时先向高端点定位；若已经在高端点到位带内，则先向低端点定位。不是断点续跑原运动轨迹。
- 故障或运行许可丢失后不自动恢复；驱动层恢复完毕后，人工游戏复位进入停止待命，再完整点击恢复。`Enable`/`Commissioned` 的重新使能只应由明确的授权操作产生。

## 导入与调用

1. 在 V18 的“外部源文件”添加 SCL，生成块；建立非保持实例 DB。所有状态、计时器和边沿记忆均设为非保持。
2. 每个 OB1 扫描调用一次；把 CPU 首次扫描信号接到 `FirstScan`，必须覆盖每次 STOP→RUN。不能仅依赖块内的 `Initialized`。
3. 程序按上面的点击切换玩法编写，另外保留独立的游戏复位输入。不要将自锁开关直接视为完整瞬时点击。
4. `Commissioned` 初始 FALSE；输入范围、速度和位置单位核实后，由现场调试人员明确启用。不要把示例定时参数当成设备额定参数。
5. 驱动层初始化完成、夹爪已停稳后，将控制权交给游戏层。退出游戏层时也必须有明确的停止/交接过程。

## 与雄克官方循环功能块的接口

官方包中的块名：`FB_SFP_EGU_EGK_Profinet_Cyclic_DATA`。

| 游戏 FB 信号 | 雄克 FB 信号 |
|---|---|
| `Ready` | `b_00_READY_FOR_OPERATION` |
| `FieldbusControl` | `b_01_CONTOL_AUTHORITY_FIELDBUS` |
| `NotFeasible` | `b_03_NOT_FEASIBLE` |
| `CommandDone` | `b_04_COMMAND_SUCCESSFULLY_PROCESSED` |
| `ReceivedToggle` | `b_05_COMMAND_RECEIVED_TOGGLE` |
| `DeviceError` | `b_07_ERROR` |
| `PositionReached` | `b_13_POSITION_REACHED` |
| `ActualPosition_um` | `di_ACTUAL_POSITION` |
| `FastStopRelease` | **游戏控制权有效时**映射到 `b_00_FAST_STOP` |
| `ControlledStop` | `b_01_STOP` |
| `MoveAbsolute` | `b_13_MOVE_TO_ABSOLUTE_POSITION` |
| `PositionCommand_um` | `di_POSITION` |
| `VelocityCommand_um_s` | `di_VELOCITY` |

驱动层中 `b_RELEASE_FUNCTION_BLOCK` 在正常循环通信时保持 TRUE。该源码并没有通过这个输入可靠阻断最后输出，不能将其当成停止开关。硬件地址由已有 PN 组态提供；其余运动命令保持 FALSE，由同一个驱动层独占写入。

**bit 0 为低有效快速停止。TRUE 表示释放快速停止；FALSE 会触发快速停止。** `FastStopRelease` 是操作层请求，不是安全信号。游戏层失能或故障会给出 FALSE；随后重新建立运行就绪必须走驱动层的人工复位/初始化流程。游戏 `ResetButton` 只清游戏状态，**不会确认夹爪故障**。驱动层必须在独立的调试/恢复模式完成快速停止释放与 `b_02_ACKNOLEDGE` 的合法时序，再把已经就绪且停稳的设备交回游戏层。禁止在恢复期间混发运动命令或自动重启。

建议每扫描先计算游戏 FB（使用上扫描保存的有效反馈），再调用雄克循环 FB 发送当前命令并刷新反馈；固定调用顺序并将额外一扫描延迟计入调试。只允许一个调用点拥有设备控制权。反馈无效时不得复用旧状态判分。

`DataValid` 要结合实际 PN 模块诊断、循环数据质量和驱动层 I/O 访问状态产生。官方 FB 没有完整公开读写质量输出，应在工程中补充诊断，不能仅用 `Ready`，更不能常量接 TRUE。网页心跳不能代替 PN 数据有效性。

## 已从官方源码和手册确认的细节

- 速度周期字段是 **µm/s**；官方 SCL 注释的 mm/s 表述与手册不一致，该源码直接传递数值，没有换算。不要把 10 mm/s 错传成数值 10。
- 源码将 `b_06_REPEAT_COMMAND_TOGGLE` 对应输出硬编码为 FALSE。此游戏块采用运动命令清零间隔后重新上升沿触发，不依赖该位；`CommandGap` 必须长于实际 PN 输出更新时间并经跟踪确认。
- 受控停止使用 bit 1；必须先看到本命令的接收 toggle 改变，再检查成功完成/位置到达，并经过固定锚点的位置稳定窗口才判分。该窗口是游戏补充判据，不是安全静止监控。
- 停止优先级高于换向：同一扫描有效点击与到位同时发生时，不再发新定位命令。
- 若有效点击发生在定位接收确认之前，进入状态 55，先收齐已有定位确认，再记录新的基准并发 STOP。定位的迟到确认不会当作 STOP 确认。
- **状态 55 会增加停止请求延迟**，通常取决于定位接收时间；确认丢失则按 `AckTimeout` 进入故障并撤销快速停止释放。该时间预算覆盖未完成定位确认及随后 STOP 确认，不是每段重新计时。该路径是游戏命令串行化，不是急停功能。现场必须测量，不能用未确认的“立即停止”承诺描述它。
- 官方源码内部依赖 GETIO/SETIO；下载页和发行说明列出 S7-1200、TIA V17 支持，但源码测试机注明 S7-1517。必须在实际 1211C/V18 工程编译核实指令版本，不能将宣传支持范围视为此 CPU 已验证。
- 同时有多个客户端发命令，会让接收 toggle 无法归属到本命令。游戏运行时关闭 Control Center 的控制功能，不允许其他逻辑确认故障或发运动命令。

## 参数与判分

所有位置为夹爪协议坐标的整数微米，不自动换算成两爪开口。先用 Control Center/手册核实零点、方向、单爪与开口关系。`VerifiedMin/Max` 和速度界限来自现场有效参数，不从规格名称“60”推算。

本回合起始时锁存行程端点、目标、容差、速度、位置稳定带和到位带；不要运行中修改滤波或超时参数。位置范围限在 0～1,000,000 µm 以内，以约束计分整数差的范围。此限制是程序约束，不是夹爪规格。

回合状态：

| 值 | 含义 |
|---|---|
| 0 | 失能 |
| 10 | 等待启动时稳定松开，然后自动开始 |
| 30 | 定位命令清零间隔 |
| 40 | 等定位接收确认 |
| 50 | 等到达本次端点 |
| 55 | 停止请求已锁存，等待未完成的定位接收确认 |
| 60 | 等停止接收确认 |
| 70 | 等停止完成与位置稳定 |
| 80 | 结果/已中止/恢复待命，保持停止，等待完整点击 |
| 900 | 故障，需要驱动层恢复与人工游戏复位 |

成功条件：绝对误差 **严格小于** 容差；等于边界为失败。结果只在 `ResultValid=TRUE` 时有效。运动中按复位会停止并中止本回合，不计成绩；停稳后一次新的完整游戏按钮点击开始下一回合。结果中按复位只清成绩，不启动运动。

| 应用故障码（不是雄克故障码） | 含义 |
|---|---|
| 0001 | 数据/运行就绪/控制权失效，或设备报错/命令不可执行 |
| 0002 | 游戏配置无效 |
| 0003 | 命令接收确认超时 |
| 0004 | 定位超时 |
| 0005 | 停止完成或位置稳定超时 |
| 0006 | 实际位置超出已核实有效范围 |
| 0007 | 人工复位中止本回合 |
| 0008 | 状态机状态非法 |
| 0009 | 操作层运动许可丢失 |

## V18/现场验证清单

- 导入生成并编译游戏块和官方块，解决所有 CPU 指令兼容性问题。
- 测试初始松开和初始按住两种情况：仅在初始化及游戏使能完成、观察到稳定松开后，才按设定自动运行。STOP→RUN 后按相同启动规则处理；现场安全回路独立决定是否允许运动。
- 跟踪松开事件、命令输出、接收 toggle、成功位、到达位、实际位置。确认停止反馈属于当前停止，特别覆盖换向瞬间点击、定位未确认时点击、接收与完成同一更新、丢帧/陈旧反馈；记录状态 55 的实际停止延迟。
- 若实际设备不能满足当前命令确认归属，需要修改驱动适配层；不得为消除超时而直接绕过确认。
- 按钮抖动只触发一次停止；检查滤波带来的实际延迟。
- 缓慢持续漂移不能通过稳定窗口；容差正负边界和恰等边界按定义判定。
- 断开 PN、丢失控制权、设备报错、命令拒绝、超时均无有效成绩且禁止重新运动。
- 运动中复位只中止，不计分；故障/许可丢失恢复需要设备恢复、游戏复位和新的完整点击，不自动重启。
- 满足现场防护后低速空载验证，再逐步调整速度和容差；不能用游戏定位命令夹持人或物体。
